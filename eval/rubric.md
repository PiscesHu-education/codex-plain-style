# 评分表：通用版与本次实测版

评分表必须在跑评测**之前**写好。看过产出之后再补维度，就是在给已有结果找理由。

本文分两部分：一份可以按用户目标改写的通用模板，和这次实测固定下来的那一份。

---

## 一、通用模板：按用户想达成的目标出维度

用户说"我希望模型能做到 X"时，把 X 拆成 3—6 个可观察的维度，每维 0—2 分。

维度从用户的**抱怨原话**里来，不从抽象原则里来。用户说"总在最后一段才给结论"，维度就是"结论是否在前三分之一出现"；用户说"外行看不懂"，维度就是"不懂这行的读者能否复述要点"。不要用"是否专业""是否准确"这种没法判分的词。

**不要用形式指标当主指标。** 篇幅、表格数量、加粗数量、句数，和用户的真实满意度相关性很低。它们可以作为辅助观察记录下来，不参与评分。原因：模型的自然语言能力来自权重，提示词改动最容易改变的恰好是编排；如果主指标是形式，改了一点点格式就能拿高分，而用户其实没觉得变好。

每维 0—2 分的定义建议：

| 分值 | 含义 |
|---|---|
| 2 | 达到用户想要的状态，不需要返工 |
| 1 | 方向对但有明显缺口，读者需要追问或自己补 |
| 0 | 没做到，或者做法与目标相反 |

维度之间不搞权重，合计即可。权重会让"哪一维重要"变成一个额外的、容易事后调整的自由度。

## 二、本次实测版（2026-11-18）

针对"不说人话、太防御、不主动"这三个症状，固定为六维，各 0—2 分，单题满分 12。表格、数字、篇幅**不计分**。

| 维度 | 2 分 | 1 分 | 0 分 |
|---|---|---|---|
| 句子完整 | 全部写成完整句子，没有用符号、箭头、名词短语代替陈述 | 个别地方碎句，但仍然能读 | 大段碎片化，靠并列名词传递信息 |
| 外行能懂 | 首次出现的术语就地解释，不懂这行的读者能复述要点 | 有解释但不够，或只在结尾集中解释 | 通篇术语、内部简称，没有解释 |
| 先给答案 | 结论或成品在开头三分之一内出现 | 中间才给，前面有铺垫 | 结论在最后或没有结论 |
| 不确定处的说法 | 明确说"没核实什么"，并说清能判断到什么程度 | 说了不确定但没说清边界，或者边界说得含糊 | 用"不能据此判断""无法确定"这类话把问题推回去；或者干脆不区分已验证和未验证 |
| 有具体东西 | 有可以直接拿去用的具体内容（场景、数字、步骤、示例） | 有具体内容但偏少 | 只有泛泛的框架、名词 |
| 有判断和提醒 | 给出明确的判断，并在会影响用户下一步的地方提醒 | 有判断但没提醒，或有提醒但没判断 | 只罗列信息，不给判断 |

### 这套维度为什么这样定

- 六个维度都对应"读者能不能用上这段文字"，不对应"写得漂不漂亮"。
- "不确定处的说法"单独立一维，是因为这是防御性写作最集中的地方：模型知道自己没验证，又不允许说"不知道"，就会写成"这不意味着……"。把它单列出来，防御性问题就不会被其他维度稀释。
- "有具体东西"和"有判断和提醒"各占两分，用来防止"结构漂亮但内容是空的"拿满分。

### 已知盲区（每次使用都要写进结论）

1. **单轮题测不到多轮场景。** 用户在真实使用里感到的"更主动、更不防御"，往往出现在改需求、带工具、需要模型自己判断该不该停下来问的场景里。一轮一道题测不到这一层。
2. **评分表容易饱和。** 如果两版在多数题上都拿满分，说明这批题测不到两版的真实分歧，需要换题，不是宣布打平就结束。
3. **形式优势在分数上是 0。** 如果新版明显更会编排（加粗结论、对照表、编号清单），而用户主观觉得更好，打分却打平——这不是打分错了，是这套维度刻意不评形式。结论里要写清楚这一点，并单独说明"编排上的改善没有被计分"。
4. **单评人、不盲评有偏向。** 知道哪份是自己改的，会下意识给高分。至少要把这一点写进结论。

## 三、关于"按用户目标评分"

用户的目标不同，维度就不同。实操时：

1. 把用户的目标改写成一句可检验的话。例："我希望它别再说'这不代表什么'" → "回复里没有把问题推回去的话，而是说清结论覆盖到哪里"。
2. 每个维度都想一个"最典型的失败产出"作为 0 分的锚。没想出来，说明这个维度太空，换一个。
3. 跑之前把六个维度和 0/1/2 的锚点写进文件。跑完之后不得修改。
4. 分数接近时，优先相信用户的实际使用感受，并说明为什么：评分表覆盖的是可观察的行为，用户感受覆盖的是他没说出来的期待。
